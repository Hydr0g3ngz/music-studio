# Benchmark 协议 v1

机器可读规则见 [protocol-v1.json](../benchmarks/protocol-v1.json)。数据清单与 SHA-256 固定在 [suite-v1.json](../benchmarks/suite-v1.json)。26 个样本全部计入完成率；失败不能从分母消失。数据下载、文件校验、模型推理与评分相互独立，支持不加载神经网络重新评分。

| 模块 | 参考数据 | 主指标 | 必须同时报告 |
| --- | --- | --- | --- |
| 歌词文字 | JamALT 完整歌曲、GTSinger 中英清唱 | 英文 WER、中文 CER，按数据域和语言汇总 | S/D/I、参考字词数、逐曲成绩 |
| 歌词时间 | JamendoLyrics / GTSinger 词时间 | 文本单调匹配后的起点误差 | 匹配覆盖率、均值、中位数、P90、200ms 内比例；不能只报成功词 |
| 旋律音符 | GTSinger 发布的实际 note_start/end | 起音+音高 F1、包含止音的 F1 | Precision、Recall、音符数；50ms / 50cent，止音容差 max(50ms,20%) |
| 节拍 | GuitarSet | F1、CMLt、AMLt | 前5秒按 mir_eval 默认排除，70ms；速度正确不代表节拍相位正确 |
| 和弦 | GuitarSet 实际演奏和弦 | 根音与大小调时长加权准确率 | 可评分参考时长比例；不把七和弦排除后的成绩说成完整和弦准确率 |
| 分离 | MUSDB 官方短预览的对应分轨 | 人声/伴奏 SI-SDR、SI-SDRi | 原始混音成绩、采样长度一致；不是整曲 SiSEC SDR |
| 运行 | 同机串行推理 | 冷进程耗时、RTF、阶段耗时 | 模型/软件版本、缓存命中、失败与重试、显存采样范围 |
| 产品 | 真实工作台及 API | 完整操作路径通过 | 删除/撤销/恢复、纠词/导出/原文保留、重启持久化、错误与响应式布局 |

每个神经推理阶段使用独立进程，避免多个框架同时常驻显存。运行时监控以 1Hz 记录整张 GPU 的已用显存，包含桌面和其他进程，可能漏过瞬时峰值。PyTorch allocator 峰值另行保留，不能当作 Whisper 的显存占用。下载耗时与缓存恢复耗时不能充当首次推理速度。

推理固定 Python / NumPy / PyTorch seed=0；bootstrap 独立使用 seed=20261015。torchcrepe 会给音高添加随机抖动，因此音符解码对照复用经过哈希验证的同一批音高曲线，神经提取的耗时与解码耗时分开记录。采样率转换的最后一个采样点允许最多 1/16000 秒的端点舍入误差；超过这个范围的反向、越界、非有限时间戳使样本评测失败。

## 比较与选择

开发样本固定在协议中，其他样本用于回归确认。这个集合此前已用于诊断，没有隐藏盲测，因此不作无偏泛化或 SOTA 结论。GTSinger 的多个唱法来自相同歌手，bootstrap 按歌手聚类，避免把相邻片段当成独立样本。很小的样本数下，置信区间仍只用于工程诊断。

先跑完整旧版，再做单模块对照。继承其他模块预测时，记录原始运行路径和文件哈希，只重跑被修改的阶段。每个比较要求相同案例和指标覆盖率；自动列出缺失项、失败及超过 5 个百分点的单例退步。不会将歌词、音符、节拍和分离加成一个总分。

开源模型的训练重叠单独标注。Beat This 的 final/small 使用过 GuitarSet，直接在这5段上得高分只能视为诊断；正式对照使用官方对应验证折的 fold checkpoint，并固定上游 split 文件。GTSinger 训练过的联合模型亦不能凭本集合入选默认。

## 局限

本集合缺少带联合词/音符标注的真实中文成品混音、足量器乐类型、长曲分离真值和独立歌手大样本。可先验证回归与工程收益，但不能声称已解决任意歌曲。原始音频与上游歌词不进入 Git，只发布清单、下载脚本、评测代码及自己产生的汇总指标。
