# Music Studio Next：音频工作台开发计划

[English](workbench-plan.en.md) · 规划日期：2026-10-16

## 方向与保留方式

从歌曲分析器发展为面向音乐、口播、环境录音与音频素材的本地工作台。普通人按目标操作，
熟练用户展开参数；每一步都能试听、比较、撤销、导出。音频处理能力与界面模板分离。

最新明确的核心定位是：**本地开源音频 AI 能力层 + Agent 工具接口 + 面向零基础用户的工作台**。
Agent（先适配 Codex）是核心操作者之一，与界面共享同一套选区、任务、候选、版本和导出。
不另做一套只能在聊天里发生的操作。模型按实际运行环境、显存、许可、离线能力登记，
任务按需选择模型并排队释放资源，不能假定所有开源模型都适合 8GB 显卡。

Codex 接入分两层：通过 MCP 让现有 Codex 调用本地音频工具；通过官方 app-server 协议
提供工作台内的持续对话、工具事件和候选试听。两层复用同一个类型化操作服务。
采用、撤销、导出和错误会同步到可视界面；不把任意 shell 命令作为音频工具接口。
协议依据 [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
与 [Codex App Server](https://learn.chatgpt.com/docs/app-server)，安装机的协议 schema 也要验证。

用户明确要求保留当前版本。`main` 与 `v0.1.2` 发布版保持独立；Next 使用
`codex/audio-workbench-next` 分支、独立 Git worktree、独立输出目录和服务端口。
不自动迁移或覆盖已有歌曲、识别版本、改字和模型缓存。现有歌曲分析与跟唱保留为经典工作流，
KTV 不作为新产品的主线。新功能通过验证后再作为可选预览交付。

## MIDI 质量：先解决可证实的问题

已有 GTSinger 评测说明 `CREPE/stable` 的音符准确性仍不足。需要分别检查：

1. **估计音高**：气声、和声串扰、低音/高音、八度跳变；有声检测与音高误差分别计分。
2. **形成音符**：重复同音的起音、辅音间隙、滑音/颤音、短音、止音。不能用随意填补休止改善观感。
3. **保存 MIDI**：绝对秒数、速度图、同音 note-off 顺序、长曲时间漂移、导入其他软件后的一致性。
4. **试听**：合成音色和识别正确性分开。提供原唱/音符/叠加对照、音量控制与区间循环，
   清楚显示这是估计结果。改进音色不作为算法准确率提升。

候选包括 [ROSVOT](https://github.com/RickyL-2000/ROSVOT) 的歌唱音符转录、
[Basic Pitch](https://github.com/spotify/basic-pitch) 的轻量 ONNX 路线，以及后续可验证的新模型。
先使用冻结 GTSinger 12 段回归，再引入 [vocadito](https://zenodo.org/records/5578807)
的独立音符与 f0 标注；不同标注者的差异单列。训练重叠、标注生成方式、语言域和阈值调参
必须记录，不能靠同一组样本调参后宣称泛化。商业歌曲仅做本地功能与听感复现，不计算无真值准确率。

默认模型的准入同时看起音+音高、包含止音 F1、有声/无声、八度错误、CPU/GPU开销和逐例退步。
若候选只对部分语言或音源有效，作为可选后端，而不是静默替换全部用户的结果。

## 工作台交互与数据骨架

- **素材库**：音频、分轨、片段、转写、MIDI、导出分别作为有来源的资产。处理链保留输入哈希和参数。
- **中间时间轴**：主时间基准不变；源音频与编辑结果分开。选区可以用于试听、分析、生成和导出。
- **右侧检查器**：简单任务给出直接动作；高级参数按需展开。处理进度不重载正在试听的音轨。
- **版本与撤销**：非破坏编辑状态独立于模型识别版本；乐观锁、防止多个页面互相覆盖；出错可恢复。
- **导出**：标明实际格式、片段长度、声道、采样率与电平；同一处理状态的试听和下载一致。
- **兼容**：双语界面、旧分析入口、已有导出格式、离线处理与无需账号的基本流程继续保留。

## 大胆的功能池

这些是发展方向，不是假装已经存在的按钮。按价值、可验证性和本机资源逐项落地。

| 想做的事 | 普通人的表达 | 专业能力与边界 |
| --- | --- | --- |
| 声音显微镜 | “这里为什么刺耳？” | 频谱/共振/削波定位，给出能试听的处理建议 |
| 声音橡皮擦 | “只留下雨声，把讲话拿掉” | 文本条件分离；保留残余轨供比较，标明误删风险 |
| 哼唱变草稿 | “把这段口哨变成钢琴旋律” | 音符转录、节奏选择、配器预览，允许保留自然演奏时间 |
| 素材寻宝 | “找到像玻璃碎裂但更柔和的声音” | 本地语义检索、相似片段和标签，不上传私人素材 |
| 场景配方 | “做成播客开场，音乐遇到讲话自动变轻” | 裁剪、淡入淡出、响度、ducking、多轨混音和可复用处理图 |
| 平行版本 | “同一段给我干净、温暖、遥远三个版本” | 可重复参数配方与响度匹配 A/B；不把音量变大冒充更好 |
| 局部重写 | “保持前后不变，把这两秒变成水下的质感” | 选区边界、上下文、交叉淡化、可选生成模型和来源记录 |
| 声音地图 | “把两小时录音中有鸟叫、笑声、音乐的位置找出来” | 事件检测、语义索引与点击定位；错误可以标注纠正 |
| 说人话的操作助手 | “剪掉长停顿，统一音量，结尾留两秒” | 将指令转为可检查的操作清单，先预览再应用；不直接执行任意代码 |

## 开源参考与工程取舍

[Waveform Playlist](https://github.com/naomiaro/waveform-playlist) 提供多轨 Web Audio 编辑参考；
[Audacity](https://github.com/audacity/audacity) 用于研究非破坏编辑与清晰的专业操作。
[DeepFilterNet](https://github.com/Rikorose/DeepFilterNet) 是语音增强候选，不能据语音效果承诺音乐无损。
[AudioSep](https://github.com/Audio-AGI/AudioSep) 可研究按描述分离；
[ACE-Step](https://github.com/ace-step/ACE-Step-1.5) 可研究局部生成与改写。
这些能力必须在独立环境测过许可、资源、质量和失败场景才接入；不在稳定版里静默下载安装。

先把资产、选区、操作、试听、任务、版本、导出这套骨架做扎实，再增加模型，避免每个模型
都带来一个互不相通的页面。性能记录使用实测，本机目标仍为 RTX 4070 Laptop 8GB。
