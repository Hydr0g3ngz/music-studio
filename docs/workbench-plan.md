# Music Studio Next：本地 AI 音乐制作工作台

[English](workbench-plan.en.md) · [本地模型候选](local-model-candidates.md) · 更新：2026-10-16

## 产品定义与优先级

目标是能创作、编曲、录音、编辑、混音和导出作品的开源音乐工作台，接入覆盖多种任务的本地先进模型。
**先把音乐制作平台和模型能力做扎实，再做 Agent 深度融合。**
零基础体现在模板、预设、解释和默认参数上；有经验的人仍然能使用完整轨道、乐器、效果器和自动化。

本修订取代此前「Agent 接入优先、继续扩展讲话清理与停顿裁剪」的实施顺序。
已有 Agent 接口和声音清理继续保留，下一阶段主线转为多轨工程、音乐创作与混音。
模型结果应交给同一份工程继续制作；模型名称列表和彼此孤立的工具页面不算完成平台。

## 保留现有版本

经典版 `main`、已发布的 `v0.1.2` 和 Next 的 `v0.2.0.dev2` 预发布版均保留。
后续开发继续使用 `codex/audio-workbench-next` 独立 worktree、输出目录与端口。
不自动覆盖已有歌曲、识别结果、歌词改字、模型缓存或旧版工程。
旧歌曲分析流程作为平台中的一种工作流继续存在。

## 平台应具备的能力

| 模块 | 用户可以完成的工作 | 工程中的表示 |
| --- | --- | --- |
| 多轨编排 | 任意长度素材叠放，拖动、切分、复制、循环、交叉淡化、吸附、区间播放 | 音频轨、片段、源区间、时间位置、小节网格 |
| 作曲与 MIDI | 导入/绘制音符、和弦与鼓点，量化、移调、力度编辑、换乐器 | MIDI 轨、钢琴卷帘、鼓机、速度/拍号图 |
| 乐器与采样 | 内置乐器、采样器、音色库，逐步接入第三方乐器 | 乐器轨、音色引用、可冻结的音频 |
| 录音 | 录人声/乐器，节拍器、倒数、多次录制与延迟补偿 | 录音素材、take、设备和监听设置 |
| 混音与母带 | 音量/声像、静音/独奏、EQ、压缩、混响、延迟、限制器、侧链、自动化 | 插入效果、总线、发送/返回、主输出与参数包络 |
| AI 音乐创作 | 描述/歌词生成音乐，参考改编、补充声部、局部重新生成 | 新轨道/候选片段，保留原作和生成条件 |
| 分轨与音频转谱 | 提取人声和乐器，转旋律/钢琴/多乐器 MIDI，分析和弦、节拍和段落 | 对齐分轨、MIDI、和弦轨、速度图、段落标记 |
| 歌声与声音制作 | 从旋律和歌词合成歌声、转换音色，生成配音和音效 | 歌词/音符对应、歌声轨、音效片段、参考素材 |
| 音频修复与变形 | 降噪、音量统一、变调、变速、时间拉伸、音乐对齐 | 可撤销效果与渲染候选；语音/音乐预设分开 |
| 素材与交付 | 管理录音、loops、one-shots、预设和模型，查找相似声音，导出作品 | 素材库、模型管理器、总混音/分轨/MIDI/工程备份 |

以上是目标能力，不是当前版本功能声明。模型及来源见[候选调研](local-model-candidates.md)。
EQ、推子、路由、节拍器等由可靠音频引擎完成；神经网络负责生成、理解、分离和转换。

## 当前底座与缺口

`0.2.0.dev2` 已有素材来源记录、不可变处理候选、任务队列、试听/导出、撤销历史、歌词改字、
分离/转写/旋律任务、响度分析和语音降噪，可继续复用。
现有 10 个能力入口包含传统算法与不同解码方式，不等于 10 个独立神经网络。

旧 Next 的处理契约仍以单条源音频为中心，现由独立 Create 工程兼容：

- `studio/models.py` 的 `MixTrack` 没有片段位置、源起点和长度；`Mix` 最多 8 个输入。
- `studio/dsp.py` 的混音要求输入长度、采样率和声道完全相同，不能用于自由编排。
- `LocalTaskRequest` 需要一份输入音频，不能从空工程生成音乐，也不支持音频、MIDI、歌词、参考等多输入。
- Create 已提供多轨引擎、乐器轨与基础音符编辑；效果路由图、速度图与录音仍缺失。

Create 使用新的轨道/片段工程与统一播放时钟，旧单音频预览继续保留。

## 实施顺序与验收

| 阶段 | 交付 | 必须能验证的结果 | 状态 |
| --- | --- | --- | --- |
| P0A 多轨工程 | 空白工程、多音频轨、片段位置/长度/源偏移、移动/切分/复制/循环、轨道增删、静音/独奏/音量/声像、保存恢复与混音导出 | 三段不同长度、采样率的素材放在不同位置，播放与导出一致；重开后位置和来源不变 | 独立开发预览已接通；片段循环等仍待补齐，见[当前范围](create-preview.md) |
| P0B 创作与混音底座 | MIDI 钢琴卷帘、鼓网格、基础乐器/采样器、BPM/拍号、效果链、总线/发送、自动化、录音与设备设置 | 从空工程写旋律和鼓点，选音色、录一轨、加效果、混音；可恢复工程并导出音频/MIDI | 已接通六种音色（含三种采样乐器）、八种鼓点、MIDI 导入与音符属性编辑；已接入固定顺序 EQ/压缩/混响和主输出限制，录音/总线等仍待开发 |
| P1 首批音乐模型 | 扩展任务契约与隔离环境，接入整曲/局部生成、现代分轨和音乐转谱 | 真实的「生成 → 分轨 → 编排/换乐器 → 混音 → 导出」，模型结果直接进入工程 | ACE-Step 12 秒器乐已实测，草稿可试听后入轨；现代分轨/转谱与完整创作验收尚待完成 |
| P2 扩展模型与制作能力 | 歌声合成、音色转换、音效/loop 生成、语义检索、更多生成/转谱后端、变速对拍与插件兼容 | 每类有可复现样例、质量/资源记录和失败说明；社区可按统一契约贡献后端 | 待开发 |
| P3 Agent 深度融合 | Agent 读懂工程并操作轨道、音符、效果器和模型，执行多步骤制作 | UI 和 Agent 使用同一工程命令与历史；过程可检查、试听、撤销 | 深度集成后置；已有适配器保留 |

P0A 首版已落地为独立制作界面，验收与限制见[预览说明](create-preview.md)。后续沿 P0B 与 P1 分批接入功能，不必等所有专业功能齐全才验证第一个创作模型。
首批优先验证 ACE-Step 1.5 的创作接口和 BSRoFormer/MelBand RoFormer 的分轨后端；
具体权重、默认模型与硬件档位由实测决定，其他候选通过同一接口接入。

继续沿「想法 → 草稿 → 编排 → 混音 → 导出」推进：首批 EQ、压缩、混响、限制器和四个混音预设已接通，见[混音验证](mixing.md)。下一批优先接入现代音乐分轨，随后补片段循环/复制编排与完整作品验收。以能完成一段作品为主线，避免只增加孤立模型入口。

首轮完整创作验收至少产出一段 30–60 秒作品，保留分轨、MIDI、效果参数、总混音和可重开的工程。
仅导出一个模型生成文件、增加模型按钮或一张界面图，不能通过该验收。

## 工程与运行架构

项目采用 `Project → Tracks → Clips`，素材独立存放。工程记录采样率、速度图、拍号图、段落和版本；
片段引用原始素材、源区间和工程位置，MIDI 保存音符与控制事件。
明确音频时间与音乐时间的换算，不能把秒直接当 MIDI ticks。
工程格式需有 schema 版本、迁移、原子保存、丢失素材定位、备份和崩溃恢复。

播放使用一个统一 transport 和调度器，任务刷新不能重建音频源；推子/独奏等调整应即时生效。
长音频使用峰值缓存、分块读取和有界内存。离线导出和实时试听共享工程语义，
验证尾音、延迟补偿、采样率转换和片段边界的一致性。

控制服务、音频播放/渲染引擎、GPU worker 分开。浏览器负责编辑与交互；低延迟录音、
设备驱动和第三方插件须验证原生音频宿主，不能以网页播放通过代替。
先比较复用现有宿主与自行实现的成本，再固定音频后端。
保留 Python 服务管理工程、任务与模型，避免 GPU 推理堵塞音频回调。

模型接入契约至少包含：

| 部分 | 必要内容 |
| --- | --- |
| 描述 | provider ID、任务能力、双语参数 schema、版本、维护状态、代码与权重分别对应的许可 |
| 输入 | 可为空或多份；音频、MIDI/曲谱、歌词、描述、参考音频、选区、BPM/调性约束；按能力校验 |
| 运行 | 独立 Python/原生环境、设备、精度、量化/offload、RAM/VRAM/磁盘估计与实测、队列、进度、取消 |
| 输出 | 有类型的音频/MIDI/曲谱/标注素材，时间基准、模型/权重修订、seed、参数和输入哈希 |
| 落入工程 | 新轨道或候选片段、目标位置、延迟/对齐信息；后台完成不自动覆盖正在编辑的内容 |
| 扩展 | 社区适配文档、示例 provider、契约检查与离线样例；用户主动安装来源经过核验的扩展 |

模型按环境隔离，不能要求所有模型共用当前 Torch/Transformers 版本。
模型中心区分「候选、支持安装、依赖可用、权重已下载、推理通过、质量已测」，显示下载量和可清理缓存。
支持 CPU、8GB、12–16GB、24GB+ 等实测档位；本机 8GB 是首个验证环境，并非整个平台的能力上限。

## 界面与零基础体验

主界面围绕制作工程：顶部播放/录音/BPM/拍号，左侧素材/乐器/模型，中间多轨编排，
下方切换钢琴卷帘/鼓机/混音台，右侧片段、效果器或生成参数检查器。
音频、MIDI 和模型候选可拖入时间轴；生成入口也可从空工程开始。

提供「从想法创作」「录一段」「改编现有音乐」等起点，以及可试听音色、混音预设和示例工程。
基础控件解释作用，专业参数逐层展开；用户可以直接完成操作，再选择是否使用助手。
Agent 后续通过侧栏操作同一工程，日常制作不依赖对话。
中英双语覆盖菜单、提示、模型参数、错误信息和文档。

## Benchmark 与发布门槛

保留现有[评测协议](benchmark-protocol.md)、[旋律报告](melody-next.md)和[语音报告](speech-cleanup.md)。
分任务维护基准，不能用一个分数混排所有模型，也不能把论文自报结果当成本机结果：

| 类别 | 需要测什么 |
| --- | --- |
| 工程/引擎 | 片段位置/循环、路由、静音/独奏、撤销恢复、导出往返、实时/离线一致、长工程内存与播放中断 |
| 分轨 | 有真值上的 SDR/SI-SDR 等及对齐、串音、瞬态损伤、逐例退步；冻结具体 checkpoint |
| 转谱/节奏/和弦 | 起音/音高/止音 F1、八度错误、复音与乐器拆分、节拍/强拍 F1、和弦加权召回；音高类别分数不冒充绝对音高准确率 |
| 音乐/音效生成 | 固定中英提示、风格/节奏/长度约束、歌词 CER/PER、盲听、片段衔接、参考旋律保留；记录全部 seed 和候选选择成本 |
| 歌声/音色/配音 | 发音、音高/时长、音色保持、可懂度、颤音/滑音与跨语言；相似度不单独代表自然度 |
| 效果/修复 | 电平/真峰值、失真、尾音、音乐保真、干净对照、等响度试听和失败样本 |
| 所有后端 | 冷启动/热运行时间、RAM/VRAM 峰值、输入长度、设备/依赖、离线运行、取消恢复、可分发状态 |

默认后端需同时满足质量、资源、许可和可维护性要求；先进候选、轻量替代、旧版基线可并存。
已有旋律跨域退步继续阻止替换经典默认，历史评测不再决定平台功能范围。
所有新功能以真实工程和运行记录验收；本规划和上游演示不表述为已交付。
